1. **`--l` / `is-faded` 只在构建时按 1180px 算一次**，但版面有 3 个容器查询档（999/759/599）。跨档失配 → 中幅 7 个、手机 6 个「无谓渐隐」，手机档出现 `--l=1` 极端失准。
   **修正了我最初的推断**（原以为窄屏栏宽变大→只会高估→安全，实测推翻）。
2. **`Secondary.astro:9` 未传 `size`** → 用默认 15，而 CSS `.secondary-body` 实际 `--fs-brief` = 14px → 系统性高估行数。

5. `max-height: calc(var(--l) * 1.7em)` 硬编码行高 1.7（注释称"各钳制元素行高均为 `--lh-body`"）—— 已核对当前成立，但属脆弱耦合。
6. 西文字宽系数（0.72/0.52）为粗略近似，en 版正文/导语普遍更长（section lead 140–220 字符），是误差风险最高的一版。

### 方案（四层，未实施）

L1 精确度量（opentype.js 读真实 advance width + 真实断行，取代启发式字宽表）
→ L2 版面预算（内容量化 → 从**有限模板库**匹配槽位，而非流式布局）
→ L3 分级降级（六档有序让步：字号→行距→去次要元素→**句边界截断**→重分配→最后才渐隐）
→ L4 验证守门（构建后真实浏览器 DOM 断言：无裁剪/无横向溢出/无孤行/填充率下限，不通过则回退 L3）

**建议取舍**：放弃「版面恒定」，接受「高度随内容漂移但收敛到有限种模板」，保住信息完整。
"完美"的可达边界：**"永不错乱"可严格保证（硬约束+断言）；"每期都惊艳"不可自动保证**（惊喜来自有意的破格，需要判断力）。

## 留白修复（同日 15:30–16:00）：中幅归零、头版 −82%

**触发**：用户已落地 v4（三档钳制 + 实测字宽 + 守门），但「大量板块底部留白未彻底解决」。

### 核心方法：留白不能用 scrollHeight 测

对无 `overflow` 的元素 `scrollHeight` **恒 ≥ clientHeight**，永远测不出留白。
必须用**子元素几何边界累加**求内容真实高度：
```js
const contentH = (el) => { /* min(top)..max(bottom) 并集 + paddingTop/Bottom */ };
gap = boxHeight - contentH;
```
已把这条并入 `verify-layout.mjs` 的 **W5** 断言（grid 项底部空白 > 48px 告警）——原先守门只覆盖裁字方向，留白是盲区。

### 三个根因（都是「grid 等高 × 内容量差异」）

| 根因 | 位置 | 规模 |
|---|---|---|
| ① `.secondary` 与 `.briefs` 同行等高 | 中幅档 @760–999px | 次条下方 **575–683px** |
| ② 简讯栏「右 4 栏纵贯两行」把整行高度推到自己高度（840px） | full 档 | 头版合计 **534px** |
| ③ 版块配额按「篇数」而非「内容量」 | `.sections-grid` | 要闻 200 / 国际 159 |

### 改动

1. **`newspaper.css`**：中幅档 + **打印档**（它复制了中幅版式，必须同改）→ `.front-grid` 单列堆叠，对齐**窄幅档早就有的**行为（窄幅实测留白本就是 0）。
2. **`newspaper.css`**：full 档头版重排 —— 头条(1–6)/次条(7–13)并肩第 1 行，正文全宽第 2 行，**简讯改底部全宽横带第 3 行**；用 `order` 控制自动放置序（不能只靠 `grid-column`，否则 briefs 会被排到正文之前）。
3. **`fit.mjs`**：`CLAMPS['section-half']` design **8 → 12**（251px 栏宽下 220 字符 ≈12.3 行，旧值裁掉约 1/3 导语）。
4. **`lib.mjs` `selectEdition`**：新增同行两块内含量均衡补稿。重量模型 `80 + min(导语,220) + 标题×1.5`——**`80` 这个每篇固定开销不可省**：少了它「5 篇短稿」与「3 篇长稿」被判等重，留白只是换个地方出现（实测科技版 Δ156）。

## 弹性排版 v5（同日 16:00–16:45）：以宽度换高度，留白归零

**触发**：用户要求「允许左右宽度不一致，板块本身也不要求等宽，动态弹性计算，最终保持左右高度一致；不渐隐、应显尽显；页面不再留空」。

### 策略（范式转变）

v1–v4 的前提是「**固定网格 + 内容适应栏宽**」→ 内容量差异只能变成**留白**或**裁字**。
**v5 反过来：栏宽适应内容量。**

同行两块要求**等高**而非等宽。高度对宽度单调递减，于是
`内容多的一侧分到更宽的栏 → 行数下降 → 高度与对侧拉平`。
解 `H_A(w) = H_B(1−w)`，二分收敛；`fr` 支持小数 → **构建时算好，零运行时 JS**。

**收益是双重的**：既消留白又消裁字（宽度弹性让内容放得下，不必再用 max-height 迁就版面）。

### 三层弹性 + 求解器

| 层 | 变量 | 载体 |
|---|---|---|
| 版块 | `--row-cols` | `.sections-row`（每行独立 grid） |
| 篇 | `--pair-cols` | `.article-pair`（并肩两篇） |
| 头版 | `--head-cols` | `.front-grid`（头条/次条） |

- 求解器：`src/lib/fit.mjs` 的 `solveRowRatios` / `solvePairRatios` / `solveHeadRatios`
  （二分 40 轮 + 单侧占比约束 `SECTION_GEO.minRatio = 0.3`）
- 高度模型：`estArticleH` / `estBlockH` / `estHeadlineH` + `SECTION_GEO` / `HEAD_GEO`

### 四条铁律（踩过的坑）

1. **参与弹性求解的元素，高度不能与宽度反向。**
   `.photo img` 的 `aspect-ratio: 3/2` 使**图片高度 ∝ 栏宽** → 加宽头条反而更高 →
   二分求解**方向反转** → en 版头条被错误推宽到 747px、空出 294px。
   修复：主图固定框高 + 估算里作为常数 `HEAD_GEO.photoH` 计入。
2. **估算必须与实际渲染同构。** `estBlockH` 初版按"并肩等分"估算，实际按弹性比例渲染 →
   块级求解误判 → 造出 106px 块内留白。改为内部也调 `solvePairRatios` 才对齐。
3. **残差下限来自行数离散性**（宽度微调若不改行数则高度不变）→ 实测残差 12–52px 是本质约束。
4. **撞 minRatio 边界是设计的一部分**（30%–70%）：内容差异极大时留残差，
   不该为提高均衡而放宽——会把一栏压到不可读。

## 副刊广告卡自适应（同日 16:51–16:55）

**触发**：用户指出中文版「订阅启事」卡片留白超多，要求自适应合适大小。

**根因**：`newspaper.css` 的 `.ad-box { height: 100% }`（注释写着"height 拉滿列高——留白成為框內呼吸"）。
`.supplement` 是 `7fr 5fr` 双栏，`height: 100%` 让广告框被拉满**副刊正文列高**；
卡片内容（三段文字 + 印章）恒定约 196px，**副刊正文越长虚胖越厉害**。

**实测 @1280px**：卡片盒子 448×**609**，内容仅 196px → **框内留白 413px（占 2/3）**。
1000px 以下为单列堆叠，卡片本就不被拉伸（20px 正常 padding）→ **问题只在双栏档**，
也因此此前逃过了守门（W5 当时只测 `.front-grid > *` 与 `.sections-row > .section-block`）。

**修复**：
1. `.ad-box` 移除 `height: 100%`，改 **`align-self: start`** → 卡片按内容收缩、贴齐列顶
2. `verify-layout.mjs` 的 W5 把 **`.supplement > *`** 纳入检测（这类拉伸虚胖以后自动捕获）

**结果**：卡片 609 → **192px**，框内留白 **413 → 0**；zh @1280 守门全绿；95 单测全过。

**遗留（不是缺陷）**：卡片与副刊正文列不可能等高（内容量差 3 倍，压到 144px 宽也不够，
而 144px 放不下印章）。卡片下方约 417px 属**版面结构**留白。
若要填满：补第二广告位/过刊导航、或 `align-self: center` 让空白上下对称、或副刊正文跨全宽另起一行。

**教训**：**"height: 100%" 是留白的常见来源**——凡是 grid 子项用 `height: 100%`
或依赖默认 `align-items: stretch` 被拉满，内容不足时就会虚胖。
排查留白时，除了量"盒高 − 内容高"，还要看子项的 `align-self` 与 `height` 是否被显式拉伸。
