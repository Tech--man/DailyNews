# 复古报纸风每日新闻站 · 开发规划

> 存档：用户 2026-09-14 提供的原始规划文档，原文照录，作为项目总纲。

## 一、产品定位

一个每天自动生成、以民国/近代报纸版式呈现当日新闻的静态站点。核心体验是"打开就是一张报纸"，而不是一个新闻 App。

三个关键决策先定下来：

| 决策点 | 建议 | 理由 |
|--------|------|------|
| 内容来源 | RSS 聚合 + LLM 改写标题 | 版权风险低，成本低，风格可控 |
| 生成时机 | 每日定时预生成静态 JSON | 用户访问零延迟，无需实时抓取 |
| 排版方式 | 模板池 + 网格系统 | 纯自动排版很难看，模板化才能稳定出片 |

## 二、视觉设计规范（先定死，再写代码）

### 1. 色板

```text
纸底    #F4EFE2   （主背景，略带黄）
纸暗    #E8E1CF   （次要区块/广告位）
墨黑    #1C1A17   （正文）
淡墨    #6B6558   （辅助信息、注释）
套红    #9B2B26   （报头、印章、栏目线）
灰调    #8C8578   （分隔线）
```

### 2. 字体

| 用途 | 字体 | 备注 |
|------|------|------|
| 报头 | 思源宋体 Heavy + 大字距，或"京華老宋体" | 免费商用需确认 |
| 标题 | 思源宋体 Bold / Noto Serif SC 700 | |
| 正文 | 思源宋体 Regular | 15–16px，行高 1.75 |
| 英文/数字 | Playfair Display / Old Standard TT | |
| 花体装饰 | IM Fell English、UnifrakturMaguntia | 仅用于报头点缀 |

中文衬线字重不够会导致"复古感"垮掉，报头建议用图片或 SVG 描边，不要依赖字体。

### 4. 版面网格

- 容器最大宽 1180px，左右留白 40px
- 12 栏网格，列间距 24px
- 正文栏宽 320–360px（报纸单栏舒适区）
- 所有区块用 1px 实线或 3px 双线分隔，不要圆角、不要阴影

│ │  +主图       │ +小图    │  +天气方块        │ │

栏目条用竖线分隔，头条区用 column-span 或直接 Grid 定位。

## 四、数据管道

```text
[每天 06:00 Cron]
   ↓
1. 抓取 RSS 源（10–20 个）
   ↓
2. 清洗：去 HTML / 截断 / 标题相似度去重（Levenshtein > 0.8 合并）
   ↓
3. 分类 + 打分：来源权重 × 时效 × 关键词
   ↓
4. 选出：1 头条 / 1 次条 / 6 简讯 / 4 分栏稿
   ↓
5. LLM 加工（可选）
   - 标题改写为 8–12 字报纸体
   - 生成 30 字导语
   - 归类到「要聞/財經/科技/副刊」
   ↓
6. 输出 issues/2026-09-14.json
   ↓
7. 触发静态构建 → 部署
```

RSS 源建议：澎湃、界面、少数派、36氪、BBC中文、联合早报、V2EX、Solidot……各取 3–5 条，避免单一来源。

LLM 提示词要点：给 3–5 个示例标题作为 few-shot，明确要求「不用感叹号、不用问句、用书面语、繁体可选」。

数据结构：

```json
{
  "issue": 428,
  "date": "2026-09-14",
  "lunar": "農曆八月初四",
  "weather": { "city": "杭州", "temp": "22~29℃", "desc": "多雲" },
  "headline": {
    "title": "秋糧入倉 全國豐收已成定局",
    "lead": "農業農村部昨日通報……",
    "image": "/img/x.jpg",
    "source": "新華社",
    "body": ["段落1", "段落2"]
  },
  "briefs": [{ "title": "…", "source": "…" }],
  "sections": [
    { "name": "財經", "articles": [ … ] }
  ]
}
```

## 五、技术选型

| 层 | 推荐 | 备选 |
|----|------|------|
| 框架 | Astro | Next.js SSG |
| 样式 | 原生 CSS + CSS 变量 | Tailwind（配置繁琐，复古风格手写更快） |
| 数据生成 | Node.js 脚本 | Python |
| 定时任务 | GitHub Actions Cron | Vercel Cron |
| 存储 | JSON 文件入 Git | Supabase / KV |
| 部署 | Cloudflare Pages | Vercel |
| PDF 导出 | Playwright | Puppeteer |

为什么选 Astro：内容型站点、零 JS 默认、getStaticPaths 天然适配"每天一期"的路由 /issue/[date]。

## 六、版面模板池（关键设计）

纯自动排版必然翻车。做法是准备 6–8 套固定版式，每天按内容特征选一套：

| 模板 | 触发条件 | 特征 |
|------|----------|------|
| A 标准版 | 默认 | 头条跨4栏 + 三栏正文 |
| B 图片版 | 头条有图 | 大图占左上 1/3 |
| C 文字版 | 无图 | 头条标题特大，全文字 |
| D 号外版 | 重大事件 | 通栏大标题 + 套红 |
| E 副刊版 | 周末 | 增加散文/广告位 |
| F 简讯版 | 新闻量少 | 简讯为主，多栏密排 |

选模板的逻辑写在生成脚本里，几行 if 就够。

## 七、开发里程碑

### M1 · 静态版式原型（2–3 天）

- 手写一份 index.html，硬编码假数据
- 目标：把字体、色彩、栏宽、分隔线调到"看着像报纸"
- 这一步不要写任何逻辑，纯粹调视觉

### M2 · 数据管道（2 天）

- RSS 抓取 + 清洗 + 去重
- 输出第一份真实 issue.json
- 先不做 LLM，直接截取原文

### M3 · 渲染层（2 天）

- Astro 组件拆分：Masthead / Headline / Columns / Briefs / Footer
- 读 JSON 渲染，套 M1 的 CSS

### M4 · 自动化（1 天）

- GitHub Actions 定时跑脚本 → commit → 触发部署
- 加历史归档页 /archive

### M5 · 打磨（持续）

- 打印样式 @media print
- 分享图生成（satori 或 html2canvas）
- LLM 标题改写
- 农历 / 节气 / 天气接口

## 八、难点与对策

| 难点 | 对策 |
|------|------|
| 中文衬线字体加载慢 | 子集化（只打包用到的字），或报头用 SVG |
| 多栏文本流动断裂 | column-fill: auto + 固定高度，或手动切段分栏 |
| 图片风格不统一 | 统一灰度 + 对比度 + 噪点叠加，弱化色彩差异 |
| 每天版面雷同 | 模板池轮换 + 头条区随机微调栏宽比例 |
| 移动端塌陷 | 桌面保留报纸感，移动端退化为单栏卡片，不强求分栏 |
| 版权风险 | 只存标题+摘要+原文链接，不存全文；图片用占位或授权图 |

## 九、可选的加分项

- 翻页动画：切换到前一天时模拟翻报纸的轻微抖动
- 咖啡渍彩蛋：随机在页脚叠加一个圆形污渍 SVG
- 印章系统：每天生成一枚随机篆刻风印章（第〇四二八期）
- 手写批注：在头条旁加一个手写体小注（"编者按"）
- 订阅：每天生成后发邮件，邮件正文就是 HTML 报纸
- 实体化：Playwright 导出 A3 PDF，可打印

## 建议的第一步

先花半天做 M1：写一个静态 HTML，把报头、双线、三栏、首字下沉、灰度图这几个元素调到位。复古报纸的成败 80% 在视觉细节，不在功能。视觉定稿后，后面全是体力活。
