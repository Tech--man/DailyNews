# 自动排版适配方案探讨

> 日期：2026-09-15 · 状态：**探讨稿，未动代码** · 触发问题：「每期内容都不同，能否设计自动排版方案适配任意内容，确保内容不确定下的完美排版」

---

## 一、结论先行

「任意内容 → 完美排版」是一个**病态目标**（ill-posed）：它隐含"完美"存在一个确定的目标函数，而内容自由度与版式自由度是耦合的。

必须把它拆成两个可回答的问题：

| 命题 | 可达性 | 依据 |
|---|---|---|
| 版面**永不错乱**（无溢出、无孤篇、无空洞、不丢句子） | **可严格保证** | 形式化约束 + 构建后断言 |
| 版面**每期都惊艳** | **不可自动保证** | 惊艳来自有意的破格，而"必须永远成立"的规则系统恰好排除了破格 |

自动化能做到的是「**永不失手**」，不是「**永远好看**」。

### 第一性原理：三约束只能取二

**内容量自由度 / 版面恒定 / 信息完整** —— 三者互斥。

| 组合 | 保留 | 放弃 | 后果 |
|---|---|---|---|
| A（**当前实现**） | 内容量自由、版面恒定 | 信息完整 | 27% 元素被硬裁，单条最多丢 9 行 |
| B | 版面恒定、信息完整 | 内容量自由 | 热点日被迫弃稿，扩容无能为力 |
| C（**建议**） | 内容量自由、信息完整 | 版面恒定 | 高度每期漂移，用有限模板库收敛 |

**关键认知**：当前系统并未真正"适配"内容，而是把不确定性**转成了残句**（内容过量时）与**空洞**（内容不足时），两个方向都没解决，只是把代价藏进了渐隐与留白里。

## 三、方案：四层架构

```
L1 精确度量   字符级字宽 + 真实断行，把"估算"换成"计算"
   ↓
L2 版面预算   内容量化 → 从有限模板库匹配槽位（取代流式布局）
   ↓
L3 分级降级   六档有序让步，先调版式，最后才裁字
   ↓
L4 验证守门   构建后真实浏览器断言，不通过就不许出刊
   ↖__________ 断言失败 → 回退 L3 降档重排
```

### L1 · 精确度量

放弃启发式字宽表，改用**离线字体度量**：用 `opentype.js` 读 Noto Serif SC / 西文字体的 `hmtx` + `cmap`，取得逐字符真实 advance width；断行用 Knuth–Plass 或精准贪心 + CJK 禁则。

- 收益：行数误差从当前 ±1~2 行降到 **0**
- 成本：引入构建依赖 + 字体文件，构建时间上升（一次性投入）

### L2 · 版面预算

把整张报纸定义为**槽位模板**而非自由流：

```js
模板 = { rows, cols: 12, slots: [{ id, colSpan, rowSpan, kind: 'headline|secondary|section|brief|ad' }] }
```

构建时：算内容重量 → 从预置模板库（6–10 个）选出匹配度最高的一个 → 打分函数 = 溢出惩罚 + 空洞面积惩罚 + 平衡度奖励。

**模板库是有限集合**，每个模板都经人工审美验证——这正是真实新闻编辑室的做法：版面是有限模板库，不是无限自由网格。**这是把"无限不确定"收敛成"有限种体面版式"的关键一步。**

| 收益 | 成本 |
|---|---|
| 内容与版式解耦，每期自动选型 | 需人工调优 6–10 个模板；模板是审美资产，无法自动生成 |
| 每期有变化，且每个变体都经审美验证 | 模板数量膨胀后难以人工审查 |

### L3 · 分级降级（核心机制）

失败时逐档让步，**顺序显式、可审计**：

| 档 | 让步手段 | 视觉代价 | 适用差距 |
|---|---|---|---|
| 1 | 字号 ±1px（限量、限黄金比序列内） | 几乎无感 | 差 1–2 行 |
| 2 | 行距 1.7 → 1.55 | 密度上升 | 差 2–3 行 |
| 3 | 去掉次要元素（图片 / 来源行 / 标签） | 信息略减 | 差 3–4 行 |
| 4 | **在句边界截断**（而非像素截断） | 丢完整句子，但不丢半句 | 差 4+ 行 |
| 5 | 重分配到简讯区 / 次版 | 版位降级 | 结构装不下 |
| 6 | 渐隐 | 视觉弱化 | 纯兜底 |

关键改进：**当前实现直接从"档 6"开始**（估算超限 → 直接渐隐 + 硬裁），中间五档全部跳过。

### L4 · 验证守门

**这是唯一能真正保证"完美"的机制**，也是最便宜、收益最大的一层。

构建后跑真实浏览器，逐项断言：

1. 每个钳制元素 `scrollHeight <= clientHeight + 1`（无裁字）
2. 无横向溢出（`scrollWidth <= clientWidth`）
3. 无孤行（末行字数 ≥ 2）
4. 填充率下限（如 `clientHeight / maxHeight >= 0.6`，防空洞）
5. 每版文章数在 1–3（版式语言的硬要求）
6. `--l` 与实际行数偏差 ≤ 1

任一不通过 → 回退 L3 降一档重排 → 重新验证。**不通过就不许出刊。**

## 四、成本与风险

| 项 | 代价 | 缓解 |
|---|---|---|
| L1 字体度量 | 构建依赖 + 构建变慢 | 一次性投入；也可只对高风险槽位（半栏导语）启用 |
| L2 模板库 | 人工调优 6–10 个模板 | 从当前版式反推，不必从零设计 |
| L3 降级阶梯 | 决策逻辑需可观测，否则难调试 | 输出决策报告（`meta.layout` 已有雏形，可扩展） |
| L4 验证闭环 | 每次构建多跑一次浏览器（数秒） | 仅 CI / 出刊时跑，本地开发可跳过 |

**最大隐性成本**：一旦引入 JS 侧布局计算，就必须保证它与浏览器渲染**逐像素一致**，否则"构建时以为不溢出，浏览器里溢出"。这是所有静态站布局预计算的通病。

> 缓解原则：只依赖可控度量（字体 advance width + 明确盒模型），**避免依赖浏览器专有特性**；并由 L4 兜底。

## 五、建议的实施顺序

**不要先做 L1**（精确度量）——那是优化，不是修复。收益顺序应为：

| 优先级 | 动作 | 理由 |
|---|---|---|
| 🔴 P0 | **先做 L4 验证守门** | 最便宜、收益最大。它会立刻告诉你当前哪 13 个元素在丢内容，且此后每次改动都有回归保护 |
| 🔴 P0 | `--l` / `is-faded` 按 3 个断点各算一套 | 修复已确认的跨档失配，无需新架构 |
| 🟡 P1 | 补齐 `count-4/5` 规则，或将每版硬性限 1–3 篇 | 修复版式语言断裂 |
| 🟡 P1 | `Secondary.astro` 补 `size: 14`；把半栏 `cap=4` 调到与真实导语长度匹配 | 消除系统性高估与 71% 误裁 |
| 🟢 P2 | L1 精确度量 | 在 L4 的保护下逐步替换启发式 |
| 🟢 P2 | L2 模板库 + L3 降级阶梯 | 结构性升级，收益最大但也最重 |

## 八、弹性排版 v5（同日 16:00–16:45）：以宽度换高度

### 8.1 策略转变

v1–v4 的前提是「**固定网格 + 内容适应栏宽**」，于是内容量的差异只能表现为**留白**（不足）
或**裁字**（过量）。v5 反过来：**栏宽适应内容量**。

同一行两块要求**等高**而非等宽。数学上很直接——高度对宽度单调递减，于是

> 内容多的一侧分到更宽的栏 → 行数下降 → 高度与对侧拉平

宽度占比可解：解 `H_A(w) = H_B(1−w)`，二分即可收敛。`fr` 支持小数，
静态站在**构建时**就能算好，不需要任何运行时 JS。

**收益是双重的**：既消除留白，又消除裁字——宽度弹性让内容"放得下"，
不再需要用 `max-height` 去迁就版面。

### 8.2 三层都弹性

| 层 | 单位 | 注入变量 | 说明 |
|---|---|---|---|
| ① 版块 | 同行两块 | `--row-cols` on `.sections-row` | 每行独立 grid；尾部单块退化为 `1fr` |
| ② 篇 | 并肩两篇 | `--pair-cols` on `.article-pair` | 版块内同样按内含量分宽，否则短篇会在导语与来源行之间空出一截 |
| ③ 头版 | 头条 / 次条 | `--head-cols` on `.front-grid` | 标题字号 h1(40px) / h2(23px) 相差近一倍，等宽必留白 |

求解器在 `src/lib/fit.mjs`：`solveRowRatios` / `solvePairRatios` / `solveHeadRatios`，
统一为「二分 40 轮 + 单侧占比约束 `SECTION_GEO.minRatio = 0.3`」。
高度模型 `estArticleH` / `estBlockH` / `estHeadlineH` 按各版式（count-N、通栏/半栏）精确累加。

### 8.3 配套改动

- **移除全部文字钳制**：`max-height` + 渐隐（`.is-faded`）、mid/narrow 的 `line-clamp` 守护网一并删除。**应显尽显。**
- **`.section-articles` 由 grid 改为逐行结构**：DOM 按版式分行（通栏篇 / 并肩对），`count-N` 类与相关选择器退役。
- **守门新增 H3（同行等高）**：同一视觉行两块盒高差 > 4px 即硬失败——这是 v5 的核心保证，必须有守卫。

### 8.4 实测（zh / en @1280px）

| 指标 | v4 | v5 |
|---|---|---|
| 同行等高差 | 47–160px | **0px**（全部行） |
| 被裁元素 | 8 个 | **0** |
| 无谓渐隐 | 12–18 个 | **0** |
| 留白告警 | 4 项（最大 133px） | zh **0** / en 1（52px） |
| 文档总高 | zh 4228 / en 3677 | zh **3876** / en **3438** |

- `pnpm verify:layout` 硬失败 **0**；**95 个单测全过**
- 页面总高反而**缩短**：内容不再被裁、栏宽按需分配，冗余空白消失

### 8.5 关键陷阱（务必记住）

1. **图片会破坏单调性。** `.photo img` 原有 `aspect-ratio: 3/2`，图片高度 ∝ 栏宽，
   于是"加宽 → 降高度"的假设失效、二分求解**反向**——实测 en 版头条被错误推宽到 747px，
   反而空出 294px。修复：主图固定框高（`.photo-main img { height: 240px; object-fit: cover }`），
   并在估算中作为常数 `HEAD_GEO.photoH` 计入。
   **凡参与弹性求解的元素，其高度必须与宽度同向或无关，不能反向。**
2. **估算必须与实际同构。** 第一版 `estBlockH` 按"并肩两篇等分"估算，而实际按弹性比例渲染，
   两者不符 → 块级求解误判 → 造出 106px 块内留白。改为 `estBlockH` 内部也调 `solvePairRatios` 后才对齐。
3. **残差下限来自行数离散性。** 宽度微调若不改变行数，高度就不变，故等高差存在下限（实测 12–52px）。
   这是本质约束，不是求解器不够好。
4. **约束边界是设计的一部分。** 单侧占比限 30%–70%；内容差异极大时撞边界留残差，
   不应为提高均衡而放宽（一栏会被压到不可读）。
5. 移除钳制后 `fitClamp3` 注入的 `--l-*` / `--fade-*` 已无人消费（组件保留以便回退），
   `verify-layout` 的 W1/W2 因此自动归零；但 `estDev` 仍会报——它测估算 vs 实际行数，
   与钳制无关，留作估算精度的监视器。

## 九、副刊广告卡自适应（同日 16:51–16:55）

**问题**：中文版「订阅启事」卡片留白超多。

**根因**（`newspaper.css`）：

```css
/* 廣告框：height 拉滿列高——留白成為框內呼吸，而非懸空 */
.ad-box { height: 100%; }
```

`.supplement` 是 `7fr 5fr` 双栏，`height: 100%` 让广告框被拉满**副刊正文的列高**；
而卡片内容只有三段文字 + 一枚印章（约 196px）——**副刊正文越长，卡片虚胖越厉害**。

**实测（@1280px）**：

| | 修复前 | 修复后 |
|---|---|---|
| 卡片盒子 | 448 × **609** | 448 × **192** |
| 内容真实高度 | 196px | 196px |
| **框内留白** | **413px（占卡片 2/3）** | **0** |

1000px 以下为单列堆叠，卡片本就不被拉伸（留白 20px 属正常 padding），
**所以问题只存在于双栏档**——这也是它此前逃过守门的原因。

**修复**：移除 `height: 100%`，改 `align-self: start`——卡片按自身内容收缩、贴齐列顶。

**守门**：把 `.supplement > *` 纳入 W5 留白检测，这类"拉伸虚胖"以后会被自动捕获。

**遗留说明（不是缺陷）**：卡片（192px）与副刊正文列（609px）**不可能等高**——
内容量差 3 倍，即使把卡片压到 144px 宽也不足 609px，而 144px 放不下印章。
卡片下方约 417px 空白属**版面结构**。若要让版面更满，有三条路：
补第二个广告位／过刊导航，把卡片改 `align-self: center` 让空白上下对称，
或让副刊正文跨全宽、卡片另起一行。
