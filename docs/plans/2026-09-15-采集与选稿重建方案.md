# 每日新報 · 采集与选稿重建方案

**日期:** 2026-09-15
**触发:** 首刊（第 429 期）内容缺失严重
**状态:** ✅ 已实施（P0 + P1 全部完成，见 §八）

---

## 一、结论

首刊「内容缺失」不是单一 bug，而是**四层叠加的系统性损耗**。核心问题有两个，一个是量的，一个是结构的：

1. **量**：素材池被无谓截断。配置里 `perFeed: 8` 把当日 **265 条**可用素材砍到 **64 条**（丢 76%），而版面最终只用 11 条。素材在入口就被扔掉，与版面容量无关。
2. **结构**：选稿层把版面**写死成「財經 + 科技」两个半版**，每版固定 1 篇。当日上版的 11 条内容，**类目分布是「財經×8、科技×3」——只有两个类目、两个来源**。國際/民生/文化/體育/要聞 五个栏目在版面上有位置、在栏目条上有名字，但**永远不可能有内容**。

此外，规划文档（`docs/dev-plan.md` §3、§4）明确要求的 **头条正文三栏**、**4 篇分栏稿**、**副刊版**，在实现里**从未产出数据**——渲染层组件都在（`BodyColumns.astro`、`Supplement.astro`），字段永远是空的。所以版面上出现了「大标题 + 80 字导语 + 大片空白」和「副刊区只有一个广告框」这两处最刺眼的空洞。

**重建方向**：不要再"先砍素材、再套死版式"，而要"**把能拿到的素材最大化，再让版面按素材自适应**"。

## 三、根因清单（按损耗量级排序）

### A. 采集层：素材入口太窄

| 编号 | 问题 | 证据 | 损耗 |
|---|---|---|---|
| A1 | `perFeed: 8` 硬截断 | 265 → 64 | **−201 条（最大单点损耗）** |
| A2 | 源池只有 8 个，且**类目结构畸形** | 科技 5 源、財經 2、國際 1、**文化/體育/民生 0 源** | 5 个栏目从源头就没有供给 |
| A3 | 无新鲜度硬门槛 | 36h 外稿件 recency 归零但仍参与竞争 | 旧闻可能上头版 |
| A4 | 源无健康度跟踪 | `minFeedsOk` 只做全量门禁，单源失败静默 | 失效源会长期占位不被发现 |

> A2 是**结构性问题**：即便把 A1 修好、265 条全进池，也拼不出一张有文化版、体育版的报纸——**因为源头就没接这些源**。这解释了为什么截图里栏目条写着「文化」「體育」但版面上没有对应内容。

### B. 选稿层：决定性缺陷

| 编号 | 问题 | 证据 |
|---|---|---|
| B1 | **无来源多样性约束** | 打分排序后 Top8 全被華爾街見聞占满 → 上版 8/11 = 73%，全页只出现 2 个来源 |
| B2 | **半版栏目硬编码 `['財經','科技']`，每版固定 1 篇** | `lib.mjs:208`；规划要求「4 分栏稿」，实际 2 篇 |
| B3 | 固定条数不随素材丰薄浮动 | 素材 64 条与 265 条出同一张版面 |
| B4 | 权重压倒数时效与质量 | `weight×8` 使 w=3 与 w=1 相差 16 分，而时效极差仅 10 分 |

> B1 的机制细节：`selectLayout` 用 `takeFirst()` 沿打分榜**顺序取走**，没有配额或去重。華爾街見聞因 w=3 + 极高时效（最新 0.2h）+ 财经关键词加成，把前 8 位全部占满，简讯栏也跟着被它填掉。**BBC中文 有 8 条进 Top30，却因排在華爾街見聞之后而一条都上不了版。**

### C. 加工层：内容厚度不足

| 编号 | 问题 | 证据 |
|---|---|---|
| C1 | **`headline.body` 从未生成** | 规划 §3「正文三栏流动（跨 8 栏）」，`[date].astro:31` 有渲染分支，但字段不存在 → 头条下方永远空白 |
| C2 | **`supplement` 从未生成** | `Supplement.astro` 永远走 `--adonly` 分支，副刊版退化成单广告框 |
| C3 | 摘要裁剪过狠且简讯**零摘要** | 头条 80 字 / 半版 120 字 / 简讯仅标题；而源普遍能给 300–999 字（实测華爾街見聞上限 999+、IT之家 400–700、Solidot 250–480） |
| C4 | 无摘要下限门槛 | 鈦媒體 17 条中仅 3 条有 ≥30 字摘要 → 无摘要条目会产出空导语 |
| C5 | 源提供的图片全部丢弃 | `parseFeed` 不解析 `enclosure` / `media:content` / `og:image` → 规划模板 B（图片版）无法触发 |

### D. 版面表达

| 编号 | 问题 |
|---|---|
| D1 | `SectionBar.astro` 硬编码 6 个栏目名、不可点，与实际版面（只有財經/科技）**不一致**——视觉上暗示有文化版、体育版，实际没有 |
| D2 | `Halves.astro` 已支持每版多篇渲染，但数据每版只给 1 篇 → 半版留白 |
| D3 | 规划 §6 的**模板池（6–8 套）完全未实现**，每天版式恒定 |

## 四、重建方案

设计原则：**放宽入口 → 规范素材 → 配额选稿 → 自适应版面**。

### §1 源池重构（修复 A1、A2、A4）

源扩到 **20–24 个**，按类目配额分布，并引入 `group`（媒體集團）字段：

| 类目 | 源 | 实测 24h 产能 |
|---|---|---|
| 要聞 | 中國新聞網（滚动） | 30 |
| 財經 | 華爾街見聞、中新網財經、界面新聞、東方財富 | 47 + 30 + 30 + 7 |
| 科技 | cnBeta、IT之家、Solidot、V2EX、開源中國、愛范兒、少數派 | 104 + 60 + 10 + 50 + 18 + 5 + 4 |
| 國際 | BBC中文、中新網國際、紐約時報中文 | 7 + 30 + 4 |
| 文化 | 端傳媒、中新網文化、豆瓣 | 5 + 14 + 5 |
| 體育 | 中新網體育 | 25 |
| 民生 | 中新網社會 | 30 |

**关键设计：`group` 字段。** 中新網有 5 个分频道源（財經/國際/文化/體育/社會）＋中國新聞網滚动源，**同属「中新社」一家**。若按「源」算多样性配额，用一家媒体开 6 个频道就能绕过约束——这是实测中发现的真实漏洞（原型 v1 里中新社两个频道同时占了要聞版两篇）。因此**配额必须按 group 计算**。

**已实测失效、不予采用**的候选源（避免下次重复踩坑）：

- 404：央視新聞、第一財經、證券時報、聯合早報、虎撲、新浪體育、網易體育、中國日報體育、果殼、三聯生活周刊、財聯社
- 401/403/超时：路透中文、懂球帝、虎嗅
- **内容陈旧**：人民網（最新条目 11831 小时前 = 1.3 年前，实为归档转储）、澎湃新聞（6549 小时前）
- **无日期字段**：新華網（300 条全部无 `pubDate`，无法做新鲜度过滤）

**健康度自愈**：抓取失败自动重试 1 次；连续 3 日出刊失败或近 7 日零上版的源标记 `stale`，在出刊日志中告警。实测中 cnBeta 在两次探测间出现一次超时（第二次成功），证明偶发失败真实存在，必须有重试。

### §2 规范化层（修复 A3、C5）

- **新鲜度硬门槛**：默认只保留 `maxAgeHours: 36` 内条目，按「今日 / 昨日 / 更早」分桶，旧稿仅在当日素材不足时补位。
- **抓取上限放宽到 25**（仅为抓取上限，非上版量），保留筛选空间。
- **`parseFeed` 补齐字段**：`enclosure` / `media:content` / `media:thumbnail` / `og:image` → `image`；`dc:creator` / `author` → `byline`；`category` / `tags` → 源侧类目提示。
- **摘要保真**：不再粗暴截断，改为**按句末标点智能裁剪**（在 `maxChars` 内取最后一个。！；？），避免半句话结尾；并设**最小摘要门槛 40 字**，低于门槛的条目降级为「仅简讯」候选，不进头条/半版。

### §3 选稿引擎（修复 B1–B4，核心改动）

把「按分数顺序取走」换成 **分版配额 + 集團多样性 + 轮转填充**：

```
版面配额（按当日素材自适应伸缩）
  頭條  1 篇   要求摘要 ≥80 字，且优先要聞/國際/財經/科技硬新闻
  次條  1 篇   要求摘要 ≥40 字，且与头条不同集團
  各版  要聞2 財經3 科技3 國際3 文化2 體育2 民生2   ← 有货才出，同版不同集團
  簡訊  8–14 条  按集團轮转取稿，单类目上限 4 条
  副刊  1 篇   从文化/长文类稿件选，填补 Supplement
约束
  单集團占全期上限 20%
  頭條与次條不得同集團
  同一版内稿件來源不得重复
```

**分类纠偏**（实测发现旧的 `classify()` 跨类污染严重）：采用「来源类目先验(3分) + 高置信词命中(2分)」加权，取最高分。旧逻辑**单一弱词即可改判**，导致「与美国贸易争端加剧 加拿大转向欧洲？」（國際）因命中 `贸易` 被塞进財經版、「核电站数据造假」（國際）因命中 `数据` 被塞进科技版。

**噪音过滤**（实测发现）：聚合索引类条目不是新闻。标题命中 `早报|晚报|日报|盘点|汇总|一览|速览|回顾` 结尾，或「标题 <10 字且无摘要」，一律丢弃。实测首刊候选里混入了「9月15日新闻早报」这类条目并一度冲上要聞版。

### §4 加工层（修复 C1–C4）

- **生成 `headline.body`**：从头条源摘要按句群切分为 2–3 自然段，喂给现有的 `BodyColumns` 三栏流动——**填掉版面最大的空洞**。
- **生成 `supplement`**：从文化类/长摘要稿件选一篇作副刊，双栏呈现。
- **简讯补一句话导语**（40 字内）。
- **LLM 层扩展**（可选，未配 `LLM_API_KEY` 全跳过，保留现有降级链）：在标题改写之外，增加「长摘要 → 80 字导语压缩」与「英文源标题翻译」。英文源（The Verge、Ars Technica 实测分别 10 条/24h、11 条/24h）是**内容量的第二增长曲线**，但需翻译层才能上版。

### §5 版面自适应（修复 D1–D3）

- 栏目条改为**由数据驱动**：只渲染当日实际有稿的栏目。
- 模板池落地 3 套起步：**A 标准版**（默认）/ **B 图片版**（头条有图）/ **F 简讯版**（素材 < 25 条）。
- 半版支持每版多篇（`Halves.astro` 已是数组渲染，数据跟上即可）。

### §6 可观测性

- 出刊日志输出**漏斗报表**：各源抓取数 → 新鲜度过滤 → 去重 → 噪音过滤 → 各版配额填充率 → 上版集團/类目分布。
- 新增 `--dry-run` 只打印报表不写文件，便于调参。
- 输出 `issues/<date>.meta.json` 记录本期来源构成，便于复盘「某天为什么内容少」。

## 五、可行性验证（已实测）

已按上述方案写出验证原型 `scripts/proto-acquire.mjs`，**两条管道各自独立抓取、独立选稿**，同一时点对比：

| 指标 | 旧方案 | 新方案 |
|---|---|---|
| 配置源数 / 集團数 | 8 | **20 / 15** |
| 每源抓取上限 | 8 | 25 |
| 抓取后素材池 | 64 | **454** |
| 新鲜度门槛 36h | 无 | 368 |
| 去重后可用池 | 64 | **346** |
| **上版条目数** | 11 | **30** |
| **上版媒體集团数** | 2 | **12** |
| **最大单集团占比** | 73% | **23%** |
| **覆盖栏目数** | 2 | **7** |
| 摘要 ≥80 字的条目 | 11 | 24 |

新版面上版构成（实测输出）：要聞 1 篇、財經 3 篇、科技 3 篇、國際 3 篇、文化 2 篇、體育 1 篇、民生 1 篇、簡訊 14 条（覆盖 11 个集團）。

**原型同时暴露了三个待解决问题**，已纳入方案：

1. **头条质量不合格**：实测头条是「国际篮球专家：中国篮球应多学习欧洲而非照搬美国」——体育评论稿，因来自综合滚动源、被判成「要聞」，靠 w=4 + 高时效抢到头条。**说明仅靠分数选头条不够，需要「权威源 tier + 多源共识（同一事件被 ≥2 独立源报道）」信号。** → 方案 §3 已加入头条类目优先级约束，但权威性信号需进一步设计。
2. **要聞版填不满**：源头仅中新社一家，被集團上限卡住，只能出 1/2 篇。→ 需补要聞源（新華網无日期字段、人民網内容陈旧，两者均不可用；候选仍待定）。
3. **體育/民生版各只 1 篇**（配额 2）：源头本身稀薄，屬客观供给不足，应在版面上按实出稿而非硬凑。

## 七、建议实施顺序

1. **P0 · 解除截断 + 扩容源池 + 集团级配额**（改 `config/feeds.json`、`lib.mjs` 选稿、`generate-issue.mjs`）→ 直接解决 73% 单源垄断

4. **P1 · 版面自适应**（栏目条数据驱动、半版多篇、模板池 3 套）
5. **P2 · 可观测性**（漏斗报表、`--dry-run`、`meta.json`）
6. **P2 · 源健康度自愈**（重试 + stale 标记）

每个阶段附单测；现有 17 个用例中 `selectLayout` 相关 3 个需随接口变更重写。

### 实施中发现并修复的**新**问题

1. **源配额必须按「媒体集团」而非「频道」** —— 中新网 5 个分频道源 + 滚动源同属中新社，
   按源计算多样性会被「一家开多频道」绕过。
2. **次条会抢空供給稀薄的版块** —— 次条排位很前且原先不限类目，实测把体育版唯一候选稿夺走。
   已为次条加类目约束 + 三级降级。
3. **英文句子分隔集缺少 `.`** —— v1 的句界集合只有中文标点，导致英文摘要永远切不出句界、
   正文永远只有一段。已改为按语言分设 `SENT_END`/`CLAUSE_END`。
4. **`buildBody` 分段数不精确** —— 固定步长 `ceil(len/groups)` 使 4 句切 3 段只得到 2 段。
   已改为边界索引均分。
5. **同版异集团约束过严会留白** —— 体育版当日常只有一家有货，硬守约束会让整版空掉。
   已改为两遍填充：先异集团，不足时放行同集团补位。
6. **`cnBeta` 抓取偶发超时** —— 两次探测间出现一次失败，证明必须有重试（已加 1 次重试 + 退避）。

### 遗留与后续

- **要闻版供给依赖中新社**：中文要闻主要来自中新社滚动源，实测该集团取用 8 条（23%），
  略高于 20% 目标。后续可增补要闻/时政类中文源（新华网无日期字段、人民网内容陈旧，均不可用）。
- **体育/文化英文源单薄**：BBC Sport 与 Variety 各为对应版块唯一来源，第二篇靠同集团补位。
- **多语言是「双版并行」而非「同稿互译」**：两版内容不同源。跨语言互译已实现但需 LLM 金钥，
  线上 CI 默认无金钥故不启用。
- **中文版改用简体**（含 UI 与内容），报头刊名「每日新報」作品牌美术字保留繁体字形。
